## Execution Flow

### Build Sequence
```
mvn package
  ↓
[Compile Phase]
  - javac compiles all .java files to classes
  - Outputs to target/classes/
  ↓
[Resource Phase]
  - Copies db.properties, create-function.sql, simplelogger.properties
  - Outputs to target/classes/
  ↓
[Package Phase]
  - Assembles JAR with manifest
  - Includes Oracle JDBC driver (7.2 MB)
  - Includes SLF4J libraries
  - Output: menu-system-console-1.0.0.jar
```

### Runtime Sequence
```
java -jar menu-system-console-1.0.0.jar
  ↓
[ClassLoader]
  - Loads MainApp class
  - Loads DatabaseConfig (triggers static initializer)
  - Loads db.properties configuration
  ↓
[MainApp.main()]
  - Checks command line arguments
  - Initializes MenuVersionDao
  - Calls createNewMenuVersion(menuId, userId)
  ↓
[MenuVersionDao.createNewMenuVersion()]
  - Gets JDBC Connection from DatabaseConfig
  - Creates CallableStatement
  - Executes Oracle stored function
  - Gets returned version_id
  ↓
[MenuVersionDao.getMenuVersion()]
  - Gets JDBC Connection
  - Creates PreparedStatement
  - Queries menu_versions table
  - Maps ResultSet to MenuVersionDto
  ↓
[MainApp.printResults()]
  - Formats output to console
  - Displays version details
  ↓
[Exit]
```

## Security Considerations

### Hardcoded Credentials
- ⚠️ Database credentials in `db.properties`
- **Mitigation**: Use environment variables in production
- See `DatabaseConfig.java` for enhancement point

### Error Messages
- ✅ Proper error handling (not exposing stack traces to users)
- ✅ Meaningful messages for troubleshooting
- ✅ Full stack traces in logs only

### SQL Injection
- ✅ No risk: Uses `CallableStatement` for function calls
- ✅ Uses `PreparedStatement` with parameter binding

### Resource Leaks
- ✅ All resources closed in finally blocks
- ✅ No resource leaks in normal operation
